# 矛盾台账｜13 组「看起来冲突」的数字，逐条判定

> 目的不是改文档，是让下一个人看到两个不同数字时**不用重新考古一遍**。
> 机器可读版本：[`二次考古复算.json`](二次考古复算.json) 的 `contradiction_ledger`；由 `考古复算.py` 的 `part_c()` 生成，内含 `literal_check` 断言（任何字面值对不上就整体 FAIL）。
> **纪律**：历史档里的「当前 / 最新 / 已验证」都是当时快照，不得覆盖，也不得因为数字不同就删档。

---

## 1. 判定分布

| 判定 | 条数 | 处理原则 |
| --- | ---: | --- |
| `VERSIONED` / `VERSIONED+DEFINITION` | 3 | 日期快照或口径差，保留旧值，只从当前控制层读新值 |
| `DEFINITION_RESOLVED` | 2 | 看似矛盾，实为分母定义不同；已算出精确差 |
| `VERIFIED` / `VERIFIED_INDEPENDENTLY` | 2 | 本轮重算吻合，可升级证据等级 |
| `PRECISION_UPGRADE` / `CORRECTED` | 2 | 近似值→精确值；上轮误标已更正 |
| `DISTINCT_SCOPES` | 1 | 两类不同对象，禁止相加 |
| `TIER_DIFFERENCE` | 1 | 证据等级差，不是数值冲突 |
| `CONFLICT_UNRESOLVED` / `UNVERIFIABLE_IN_REPO` | 2 | 明确写「缺什么」，不假装定案 |

## 2. 逐条

### N01 文件数：610 / 625 / 640 / 647 → `VERSIONED+DEFINITION`

610 是 11-03 v2 体检时的文件数；625 是 `e1d6861` 的 `git ls-files`；**640 是当前「非生成文件」清单行数**，**647 是当前跟踪文件总数**，差 7 个生成产物（自哈希循环不计入逐文件清单）。恒等式 `640 + 7 = 647`。不是冲突，且不能把 610 写成「现在的文件数」。

### N02 检查数：21/21 → 29/29 → 32/32 → `VERSIONED`

`48a6b6f` 21 项、`e1d6861` 29 项、本轮 32 项。维护日志里 21/29 是当时运行结果，**保持原样**；当前值以 `python3 tools/verify_repo.py` 输出为准。

### N03 链接数：537 → 603 → 619 → `VERSIONED`

每新增一份带链接的文档就会增长；旧数字是当时快照。当前 `619 条本地链接 / 0 断链`。

### N04 520 vs 522 → `DEFINITION_RESOLVED`

从 690 事件表逐事件重算：`522 = 516 .cpp + 4 .cc + 2 .py`；`520份赛时C++非空源码快照.jsonl` 只收 C++，即 `516 + 4`。差的 2 条是 `contest_replay_capture.py`（42,371 B，sha16 `7cdacb9042e6`，同一内容两种路径拼写）。**不是丢数据，是语料定义不同。** 同一规则解释第 2 场版次索引 76 行（78 − 2）。

### N05 3518/5912 vs 3518/5913 → `DEFINITION_RESOLVED`

`5912 = Σ_{n=2..7} n!`，`5913 = Σ_{n=1..7} n!`。n=1 的那 1 例三版都正确，所以错例数都是 3,518。历史文档用 n≥2 口径，本轮脚本两个口径都打印，避免「分母差 1」被误读成算错。见 `01` §3。

### N06 Day1 A 五条历史断言 → `VERIFIED_INDEPENDENTLY`（`[R]` → `[E]`）

`3518/5912`、`n=3 错 1/6`、`n=4 错 7/24`、`n=6 错 378/720`、`v4 0/5912`，以及两个最小反例 `[3,1,2]`、`[2,1,3,4]`，全部由编译后的真实源码 + 独立真值跑出来。详见 `01`。

### N07 Day4 合法率：`≈0.0282690368` / `0.0282` / `38971267793/1378584918490` → `PRECISION_UPGRADE`

后两者是不同精度，精确值统一从 `交接/2026-11-03_远古数据复算/历史数值复算.json` 读取；历史文档里的近似值**不改**。

### N08 `#26 = .clear()` → `CORRECTED`

`错因总表.csv` 的 #26 是「SPJ/多解构造题缺计分检验器」；`.clear()` 是 `考场执行卡_NOIP.md` 的「跨界死穴」。上轮草稿误标已更正；编号写错会污染 28 条病因的聚类统计。

### N09 CodeLands2 40/61 → `CONFLICT_UNRESOLVED`

两轮转写互相冲突，仓库无官方逐提交 record、无第 2 场计分协议、无附件正文。本轮复算出 126/78/36/22/8 等**事件层**数字与 4 份源码哈希，但没有一条能推出分数。详见 `02`。

### N10 CodeLands3 160 `[G]` vs `[OJ] UNKNOWN` → `TIER_DIFFERENCE`

`赛事账本.json` 明确 `score=160, score_tier=GEMINI_REPORT+USER_REPORT`。这不是两个数打架，是「有人这么说」与「官方记录缺失」并列。`verify_codelands3_candidates_v2.py` 通过也**不**把 160 升级为 OJ。

### N11 附件 5/8 与 4/8 → `UNVERIFIABLE_IN_REPO`

SHA 目录里能看到 `zerofree1.in` 19 B、`zerofree5.in` 1,325,704 B 等指纹，但**正文不在 Git**。这两组比率是上轮在外部桌面附件上实测的 `[R]`，本轮不声称重跑，也不拿它反推分数。

### N12 729/3600 与 28 条/40 次 → `VERIFIED`

从 `赛事账本.json` 重新筛 `in_main_line && OJ` 得 9 场、729/3600；`错因总表.csv` 28 行、`仓库口径次数` 合计 40。脚本内 `assert`。注意 #21–#28 是 11-03 转写 PDF 新增且计数为 0，**不可并入 40 次分母**。

### N13 1548 组对拍 vs 57 组正式数据 → `DISTINCT_SCOPES`

`验证报告.json` 的 403+403+506+236 = **1,548** 是随机/解析对拍次数；`data_manifest.json` 的 **57** 是正式评测点（114 文件，捆绑总分 400）。两者对象不同，**不能相加成「1605 组测试」**，也不能拿对拍次数当评测点数量。

## 3. 使用方式

1. 看到两个数字打架，先在本台账查 `verdict`；`VERSIONED` / `DEFINITION_RESOLVED` 直接读解释，不要改旧档。
2. 想确认当前值：`python3 交接/2026-11-03_二次考古与矛盾对账/考古复算.py`，脚本会重算并断言字面值；若某天数字真的变了，`literal_check` 会 FAIL 并列出 `checks_literal_failed`，这时才需要新增一条台账记录。
3. 遇到 `CONFLICT_UNRESOLVED` / `UNVERIFIABLE_IN_REPO`，按 `02` §4 的字段清单去补证据，**不要用推理把缺失填上**。
