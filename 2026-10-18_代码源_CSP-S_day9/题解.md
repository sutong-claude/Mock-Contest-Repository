## A｜后藤一里的数组

**标签**：操作次数建模、相邻差、倒序贪心。难点是可行性，不是算一个最大值。范围：单组n≤10^5，总n≤10^6，a≤10^12。

### 1. 把故事压成一个动作

选择偶数k，把前k项分别加1、2、…、k。目标非降，最少操作。n=1本来有序，答案0。

对子任务：n≤2是10分，n为偶数是30分，a≤10是20分，全数据40分依赖前3组。另有“所有有无解均正确可得该测试点50%”规则，但本次实际60来自前3个子任务满分。

先看相邻差d_i=a_i-a_{i+1}。一次操作有三种影响：

| 前缀k和边界i的关系 | d_i的变化 |
|---|---:|
| k<i | 0 |
| k=i，只有i为偶数才允许 | +i，变得更难 |
| k≥i+1 | -1，变得更容易 |

因此下降量D=max(0,max d_i)是操作次数下界。n为偶数时对k=n做D次即可，答案D。

### 2. 从“选哪种操作”换成“每个位置被覆盖几次”

令x_i为总共覆盖位置i的操作次数。最终高度是

\[
b_i=a_i+i x_i.
\]

由于操作都是前缀：

\[
x_1\ge x_2\ge\cdots\ge x_n\ge x_{n+1}=0.
\]

由于不能选择奇数长度，奇数i满足x_i=x_{i+1}。偶数i的差x_i-x_{i+1}，正是选择长度i前缀的次数。由这些差可以反向构造全部操作，所以这个表示**既必要又充分**，没有丢信息。总操作数为x_1。

非降要求对每个i<n有

\[
a_i+i x_i\le a_{i+1}+(i+1)x_{i+1}.\tag{1}
\]

这就是你赛时“前面要足够，后面不能顶爆”的完整版本。不能只检查最大下降发生的位置，因为其他边界也限制容量。

### 3. 为什么有解时答案一定就是D

任意可行方案中，由(1)可得

\[
a_i-a_{i+1}\le x_{i+1}-i(x_i-x_{i+1})\le x_1.
\]

所以x_1≥D。接着，把所有x_i一起截断成y_i=min(x_i,D)。它仍然非增，奇数位置的相等关系也保留。

只需证明非降仍成立：

- 两边都未截断，原约束不变。
- 左边被截断、右边未截断，左侧高度只会下降，约束更宽松。
- 右边被截断，因为x_i≥x_{i+1}，左边也截成D。此时 `a_i+iD≤a_{i+1}+(i+1)D` 等价于d_i≤D，由定义成立。

因此任意有解输入都有一份最多D次的方案，再结合下界，最优值恰为D。[P]

这证明了为什么“只判有解拿一半”并没有绕开核心问题。

### 4. 倒序求最大允许覆盖次数

现在只寻找0≤x_i≤D的可行序列。从右向左已确定x_{i+1}=t。

- i为奇数：只能令x_i=t，检查(1)。
- i为偶数且i<n：由(1)，

\[
x_i\le \left\lfloor\frac{a_{i+1}-a_i+(i+1)t}{i}\right\rfloor.
\]

所以尽可能取右侧上界与D的较小值；还必须x_i≥t。若不满足则无解。
- i=n且n为偶数：右边没有高度约束，直接取x_n=D。

最终x_1必须等于D；否则无解。

**为什么可以尽可能取大？** 取更大的x_i，会让左邻更容易被它托住。对偶数位置，容量上界是t的单调非降函数；约束“容量至少t”等价于 `a_{i+1}-a_i+t≥0`，也随t增大而更容易。奇数位置检查条件等价于d_i≤t，同样随t增大而更容易。故若有任何可行后缀，贪心得到的次数不会比它小；若贪心当前失败，更小的后缀次数也不可能救活。按位置归纳，贪心完整。[P]

用 `__int128` 做乘积和容量分子，避免把数值范围证明埋在long long中。复杂度O(n)，额外空间O(n)用于输入，求解本身O(1)。

### 5. 沿原倒扫的最小结构修复

保留你算ma、由右往左、维护sum的思路。循环处理i时：sum是“已经决定、长度大于i的操作次数”。先把它对当前位置的影响加上；再决定长度恰好i的新次数go；立刻把go对当前位置的影响也加上。

```cpp
int sum = 0;
for (int i = n; i >= 1; i--) {
    a[i] += sum * i;
    if (i % 2 == 0) {
        int go = min(ma - sum, max((a[i + 1] - a[i]) / i, 0LL));
        sum += go;
        a[i] += go * i;  // 新操作也覆盖当前点
    }
    if (i < n && a[i] > a[i + 1]) {
        cout << -1 << '\n';
        return;
    }
}
cout << (sum == ma ? ma : -1) << '\n';
```

这里沿用了原程序的long long宏和a[n+1]哨兵；次数被ma封顶，在本题范围内乘积≤10^17。与完全按覆盖次数写的主实现不同，这份代码用于解释原程序怎样修。完整修复已过10001组与主解交叉检查、四份附件；这10001不是独立真值对拍，独立真值数字另列。

反例 `[7,1,7,1,1,1,13]` 的旧输出6、正确-1及无解证明见复盘。没有宣称它是数值域全局最小反例。

## B｜山田凉的片段

**标签**：贪心、先后插入、区间阻挡、有序集合。n和a均≤10^6。子任务分值10/15/20/20/35，对应n≤8/20/300/5000/10^6，依赖逐级累积。原HTML中两个20分共用rowspan，不能把第四行当成没有分值。

### 1. 先手玩三个数

`2 1 3`，只按下降位置切会得到 `[2] | [1,3]`。第二段既不能放2前面，也不能放后面，所以最少3段。

对照 `3 6 4 5`：可以 `[3,6] | [4,5]`，后来的[4,5]可以塞到前段内部，答案2。这两个例子共同表明，不能只检查最终值域是否重叠；要看重叠发生时谁已经在序列里。

### 2. 一段什么时候能合法插入

处理当前段之前，原数组前面的全部元素已经插入。若最终要有序，这些旧元素当前就必须有序，因为后续插入不会交换旧元素。

设当前段最小值mn、最大值mx。合法的充要条件是：

1. 当前段自己非降。
2. 旧元素中没有任何值y满足mn<y<mx。

必要性：若旧数y严格夹在两端中间，当前整段无论放在y之前或之后，都产生逆序。

充分性：旧元素均≤mn或≥mx（等于端点允许），就在这两类之间插入整段即可。mn=mx时，任意合适的等值位置都可以。

注意“旧元素”是当前段开始位置之前的全部元素，不包括当前段前面刚扫描的部分，也不包括未来元素。[P]

### 3. 贪心：当前段能延长就延长

从左到右增长当前段。如果新数小于段尾，必须切；否则判断旧元素中是否出现严格位于 `(段首, 新数)` 的值。有则在新数前切，无则继续。

用set维护所有已经结束的段的元素。用 `lower_bound(newValue)` 找第一个≥新值的位置，退一步得到最大的严格小于新值的旧数；它若>段首，就有阻挡。切段时，将刚结束的段整体加入set。

不要把当前段每扫到一个数就放进set，否则会把自己误当成旧障碍；也不要只检查 `(前一个数, 新数)`，因为重复值会让早先留在较大开区间里的障碍逃过检查。

### 4. 最长前缀为什么最优：交换证明

固定已经处理的前缀。设贪心第一段结束在g，任意最优方案的第一段结束在p。由于g是从当前起点能取的最远合法位置，p≤g。

把最优方案从当前起点到g的部分合成贪心这一段。它合法，已由判定保证。原最优方案中完全被吞掉的段删除。如果g切入原方案某一段内部，保留该段剩余后缀：

- 后缀仍有序；
- 新成为“旧元素”的，只多了原同一段被截走的前缀；这些数≤后缀最小值，不会落到后缀两端的开区间；
- 其余先前元素集合与原方案相同，不产生新障碍。

更后面的段开始前，已经处理的元素集合与原方案完全相同，所以合法性不变。总段数不会增加。于是存在一个最优解以贪心段开头，递归应用得到全局最优。[P]

每个元素最多插入set一次，每个扫描位置至多一次查询。时间O(n log n)，空间O(n)。值域只有10^6，也能用树状数组做区间计数，但不是理解本题的必要门槛。

### 5. 与原代码的关系及部分分

原稳定排序得到逆排名f，再数f[i]>f[i+1]。稳定排序保证这恰等价于原a[i]>a[i+1]，所以最终算法实质只是数非降段。无论怎么调整归并实现，都不会增加“已有旧数阻挡”这条条件。

小数据可靠方法：DP枚举每段[l,r]，显式尝试插入已排序前缀的所有空隙。因为任何可行历史的前缀最终有序，其排列由多重集唯一决定，不需要保留指数多种前缀排列。用它做独立oracle。更快的中等规模DP可用合法段判定，先O(n²)生成/查询合法性，再转移；完整解法则用上述交换证明消去DP。

## C｜虹夏的传送门

**标签**：时间图、支配关系、事件压缩、多源传播、单调二分。N、M、Q均≤2×10^5，时间0..10^9。门有向、只在指定时刻可用、传送耗时0、可等待、同一时刻可以连续走多条门。

| 2 | 14 | N,M≤1000，Q仍可20万 | 1 |
| 3 | 15 | 所有查询U=1 | 无 |
| 4 | 18 | 所有T≤100 | 无 |

### 1. 为什么你的最终两阶段算法是正确的

到达房间u的最早时刻为d[u]。门(u,v,t)可用当且仅当d[u]≤t，此时到达v的候选是t，不是d[u]+t。因为能等待，更早到u支配更晚到u。于是按到达时间从小到大取点、松弛可用门是正确的时间版Dijkstra。

从U的0时刻开始跑一次得到最早到S的x。任意合法路线访问S的时刻不会早于x，而我们到S后可等到那个时刻再复制其后半段。因此从(S,x)再跑一次就是全局最优。[P]

最终代码还正确处理U=S、V=S、不经过S却直接到V的非法路线，以及到S后立刻离开的情况。真正失败原因在Q次重算，不在这层模型。

### 2. 第一层消重：相同起点

同一U的所有询问只需两次最短路。把询问按U分组，跑完得到所有终点答案，再写回原查询顺序。

若不同起点数K，时间O(K(N+M)log N+Q)，空间O(N+M+Q)。对应前三个子任务K≤9、K≤1000、K=1分别有可用规模依据；对应附件已实测通过。完整代码保留了你的两阶段路线，只重构外层询问组织。

### 3. 第二层消重：把“房间＋有用时刻”变成点

所有有意义的移动只发生在传送门时刻。对每个房间收集它作为门起点或终点的时刻，排序去重；额外给S加入时刻0。

建立事件节点(u,t)：

- 同一房间相邻事件 `(u,t1)→(u,t2)`，表示等待；
- 每个门 `(u,v,t)` 变成 `(u,t)→(v,t)`。

至多2M+1个事件节点，等待边至多事件数，门边M。总规模O(N+M)。相同时刻可能有环，不使用“假设时间严格增加”的DAG DP。

从U的0时刻可以先等到U的第一个事件。因此U≠S时，它能否到S，由其第一个事件决定。U没有事件且U≠S，当然无法访问S。U=S时到S最早就是0。

### 4. 反向最小标签：每个事件最早能在什么时候到S

对S的每个事件(S,t)，赋初始标签t。在事件图反图中，把较小标签向前驱传播。用最小堆，每次取当前最小标签：若某前驱能到这个事件，也能最终在标签时刻到S。

最终 `earliest[v]` 等于所有从事件v可达的S事件时刻最小值。证明可以直接从可达性定义出发：每次传播对应一条合法路径，故不会生成虚假时刻；任何合法路径的终点S源标签会沿反图逐边传回，故最小值不会遗漏。优先队列只负责高效达到这个闭包。[P]

于是每个起点U都得到x=最早到S的时间。

### 5. 正向最大标签：到某个事件前，最晚可从S何时开始

同样给每个S事件(S,t)初始标签t，在正图中传播**最大值**。最终

`latest[v] = 能到达事件v的S事件时刻的最大值`。

不可达为-1。用最大堆传播，语义和上一段对称。注意标签是“从S出发的最晚时刻”，不是“到事件v的最晚时刻”；事件自己的时刻已经固定。

查询到S的时间是x。事件v可接上当且仅当latest[v]≥x：

- 若latest[v]=s0≥x，先在S等到s0，再走那条路径即可。
- 若存在从(S,x)到事件v的路线，选它从S使用的起始事件时刻s0。必有s0≥x，故latest[v]≥s0≥x。

V=S的情形也一致：S自身事件初始化保证其标签至少是自身时刻；所有边时间非降，不可能标签超过该事件时刻，因此正好相等。

### 6. 为什么能对终点事件二分

同房间事件之间有等待边，故latest沿时间顺序单调非降。对V的事件数组找第一个latest≥x的位置，其事件时刻就是最早到V。若不存在则-1。

**同一时刻连续穿门怎么办？** 对应同一时间层内部的有向边和环，优先队列的松弛传播直到稳定，不依赖输入边排列；所以零时刻、自环、同刻链与同刻环全部在模型内。独立oracle刻意使用同刻反复闭包来检查这一点。

构图排序O(M log M)，两个传播O(M log M)，Q次二分O(Q log M)，加N个房间初始化，总计O(N+(M+Q)log M)，空间O(N+M)。

## D｜子集异或：按定义做子集和

**标签**：子集和覆盖区间、二进制值域分层、双指针、前缀和。n≤5×10^5，a≤10^18，答案模998244353。子任务10/15/20/25/30，n上限10/500/5000/10^5/5×10^5；第2—4组a≤10^9（原表是rowspan），最后组a≤10^18。按依赖整包计分。

### 1. 单个数组的F怎么算

把元素从小到大排序。初始能表示的和只有0，令f=1，表示第一个目前不能表示的正整数。

看到数v：

- 若v>f，所有后面的数也≥v，任何新子集和都不能填出f，答案就是f。
- 若v≤f，原来能表示[0,f-1]，选v后还能表示[v,v+f-1]，两个区间连续衔接，合起来能表示[0,f+v-1]，令f+=v。

例如[1,5,2]排序为1,2,5：f从1→2→4，看到5>4停，F=4。[P]

枚举所有区间再排序可得可靠朴素解；n≤10甚至能直接枚举每个区间所有子集。独立oracle采用后者，没有与主解共用硬币贪心，避免同错。

### 2. 一层数值要么全吃，要么全不吃

把数值分桶：B_k=[2^k,2^(k+1))。令low=2^k、high=2low。

按升序处理时，若桶里第一个数v能被吸收，吸收前f≥v≥low，吸收后f+v≥2low=high。桶内所有其他数都<high，所以都会被继续吸收。

因此对于一个区间：

- 若桶里有数，至少一个能吸收就等价于整桶能吸收；
- 桶被吸收后最终F≥high；
- 若最终F≥high，那么所有小于high的数都必然被吸收，否则停止位置会让F<high。

设该区间桶k元素之和为W_k，便有

\[
F(l,r)=1+\sum_k W_k(l,r)\,[F(l,r)\ge 2^{k+1}].\tag{2}
\]

空桶W=0，自然不贡献。别把“桶里只看最小值”误读成“最终只加最小值”；合法性看最小值，贡献要加整桶总和。

### 3. 不求每个F，改求越过每个阈值的区间

定义L_k(r)：使F(l,r)≥2^k成立的最大左端点l；没有则0。

正整数集合加元素不会减少可表示的和，因此不会让F变小。故固定r时合法左端点是连续前缀 `[1,L_k(r)]`；固定k时L_k(r)随r单调非降。初始F≥1恒成立，所以L_0(r)=r。

这正是双指针需要的单调性。

### 4. 已知L_k，怎样求L_(k+1)

只考虑l≤L_k(r)，这些区间已经保证F≥low。设W为区间内所有 `<low` 的数的总和，mn为当前桶 `[low,high)` 内最小元素；若桶空则mn=∞。

由于已经保证F≥low，所有小于low的数都已被吸收，处理完低桶后f=W+1。要达到high，仅有两种可能：

1. W+1≥high，即 W≥high-1，不用当前桶已经够了。
2. 当前桶有数且mn≤W+1，能吃进第一个数，随后整桶都能吃，立刻达到high。

于是准确判定为

\[
l\le L_k(r)\quad\text{且}\quad
(W\ge high-1\ \lor\ mn\le W+1).\tag{3}
\]

这里对l≤L_k(r)的前置限制绝不能省。没有它，仅有很多较大数的总和，并不代表较小的缺口都已经填上。

从左到右扫r，用一个移动左端点l维护：

- W：窗口内小于low的元素和；
- 单调队列：当前桶元素最小值；
- 前一层L_k(r)：限制最多能收缩到哪里。

当(3)成立就继续右移l、删去对应元素。循环结束后，最后一个合法左端点为l-1，因此L_(k+1)(r)=l-1。

一个元素每层只进出窗口一次，单调队列每个下标最多入队出队一次。每层O(n)。

### 5. 合法区间的整桶总和怎样一次算完

设P_k(r)为前r项属于桶k的元素和。根据(2)，固定右端点r，本层贡献是

\[
\sum_{l=1}^{L_{k+1}(r)} (P_k(r)-P_k(l-1)).
\]

令L=L_(k+1)(r)，化为

\[
L\cdot P_k(r)-\sum_{j=0}^{L-1}P_k(j).
\]

P再做一次前缀和即可O(1)计算。最后再加每个非空区间的基础1，共n(n+1)/2。

复杂度O(n log A)，A≤10^18所以最多60层；空间O(n)。维护W要用128位整数，因为最多有5×10^5个10^18，总和可以远大于64位。答案用模数前缀和，但**用于判定的W不能取模**。

### 6. 手推一整层看它是不是玄学

仍取[1,5,2]。六个区间的基础贡献为6。

k=0，桶[1,2)只有1。凡包含这个1的区间都达到F≥2；它们是[1]、[1,5]、[1,5,2]，各贡献1，总加3。

k=1，桶[2,4)只有2。只有[1,5,2]能把F推进到4，贡献2。

k=2，桶[4,8)有5，但包含1、2时处理前f=4，仍吃不进5，贡献0。

总和6+3+2=11，与逐个区间答案完全一致。这也说明值域分桶不要求原数组排序：排序只是证明单个集合F的工具，真正统计依靠原数组区间窗口。
