### 最终循环按语义拆开

原代码：

```cpp
a[i] = a[i] + sum * i;
// 这里仅加入之前决定的长前缀影响
int go = (a[i + 1] - a[i]) / i;
go = max(go, 0LL);
sum += go;
now += go;
// 少了本次go对a[i]的影响
int cha = a[i - 1] - a[i];
// 左边还是原值；右边只加入部分操作，不能作为最终相邻高度差
```

另一个结构问题是只扫到最大落差pos：它把“证明下界的位置”当成“所有可行性约束的代表”。修正版扫描全数组并逐对验证最终高度，不再依赖pos。

七项反例中，旧程序选了长度6操作2次；在长度4只保留2次覆盖，却没有发现第三项13大于第四项9，最后又在长度2补4次并宣布总6可行。真正操作后的数组为 `[13,13,13,9,11,13,13]`，中间仍逆序。返回答案数字6并不等于构造出了可行数组。

## B：9个main保存

045实现归并；046在排序后索引上数下降；047加调试输出；048换std::sort；049构造逆排名f；050打印f；063去调试并开文件IO；064回归自写归并；065清理最终保存。

这条链说明你确实做过实现研究，不能说“只写了一个tot++”。但从049到最终065，输出的数学量仍是原数组非降段数。稳定排序改变相等项的排名安排，不能让当前段跨过已存在的旧数。

三项反例：n=3，a=[2,1,3]，最终f=[2,1,3]，程序答2，实际3。n≤2不可能产生“旧元素严格位于一个新双元素段中”的障碍，因此这是按长度最小的这类反例。

附件五份全错，第一份真实输入的排名输出由关键帧确认，不是因为赛后读取到了另一版。最终恢复归并没有修复缺失的合法性条件。

## 哪些代码版本不应被叫作稳定版

- 只有保存和编译，没有针对子任务的验证：S-code。
- 只有一份样例过，没有规模检查：最多局部S-verify。
- 已有数学证明但没保存独立可交文件：是算法资产，不是文件冻结。
- 本轮没有发现赛时独立命名的A40/C19冻结文件。A40可以由保存021恢复；C19则连资源合同都未闭合。

这些层次用于准确记账，不是否定你在比赛里的努力。
