# AI 吞入包｜使用说明（2026-11-03）

> 给**没有 Agent 能力**的 AI：你不必遍历 610 个文件，也不必猜哪份文档最新。按下面顺序读，就能完整吞下这个仓库。
> 本目录由 `python3 tools/build_repo_state.py` 维护 `01`/`MANIFEST`，`02` 为人工编纂。全部文件**不手改生成物**。

## 三层吞入法

| 层 | 读什么 | 体量 | 得到什么 |
| --- | --- | --- | --- |
| ① 骨架（必读） | `02_全仓库知识骨架.md` | 约 1 文件 | 全仓库事实、口径、矛盾、目录、SOP、NOIP 计划的压缩版 |
| ② 画像（必读） | `../用户画像_2026-11-03.md` | 1 文件 | 仓库主人会什么、不会什么、为什么丢分、怎么协作 |
| ③ 展开（按需） | `../START_HERE.md` → `MANIFEST.json` 的 `read_order` | 14 个入口 | 精确规则、账本、逐场复盘、执行卡、队列 |
| ④ 细节（按需） | `../../总览/仓库全量清单_2026-11-03.csv`、`01_逐文件摘要.jsonl` | 610 行 | 每个文件的路径/字节/SHA/分类/读优先级/标题/摘要/异常标记 |
| ⑤ 全文（按需） | `python3 tools/export_ai_corpus.py --out <路径>` | 按 `--max-bytes` 分片 | 所有文本文件的完整正文，带路径与 SHA 头 |

## `01_逐文件摘要.jsonl` 怎么读

一行一个 JSON 对象，字段：

```json
{"path":"…","bytes":123,"sha256":"…","category":"比赛归档","read_priority":2,
 "encoding":"utf8","title":"…","summary":"…","headings":["…"],"flags":["DUP"]}
```

- 流式读入（不要一次性拼字符串）：`for line in open(...)` 逐行 `json.loads`。
- 过滤：`read_priority<=1` 得到控制层与交接层；`category=="比赛归档"` 得到逐场证据。
- `flags`：`EMPTY` 空文件、`BINARY` 非 UTF-8、`LARGE` >1 MB、`DUP` 内容重复、`TODO_MANY` 待办密集、`LEGACY_ID` 含历史自有目录名、`ENTRY` 已降级历史入口、`CONTROL` 控制层、`GENERATED` 自动生成物。
- `encoding=="binary"` 的 9 个文件是录屏/PDF/ZIP/DOCX，导出全文时默认跳过。
- **清单里没有 7 个自动生成物**（清单/摘要/MANIFEST/账本/索引）：它们由 `build_repo_state.py` 每次重算，若把自身 SHA 写进自身会形成永不收敛的循环。它们的路径、字节数与 SHA 记录在 `MANIFEST.json` 与 `../仓库文件索引_2026-11-03.json` 的说明字段中；`tools/export_ai_corpus.py` 导出全文时会把这 7 个也一并收录。

## `MANIFEST.json` 里有什么

`file_count` / `total_bytes` / 分类与读优先级分布 / 分片记录数与 SHA-256 / `read_order`（14 个入口的推荐顺序）/ 全文导出与批量导入命令 / 边界声明。**分片 SHA 用于确认你手上的 `01` 没有被改过**：`python3 tools/verify_repo.py` 会重算并逐字节比对。

## 超大规模读入

```bash
# 导出全部文本正文（自动按文件边界分片，绝不截断半个文件）
python3 tools/export_ai_corpus.py --out 总览/AI吞入包/_导出/全仓库正文.txt --max-bytes 8000000
# 只要控制层 + NOIP 相关，且只要 JSONL 索引
python3 tools/export_ai_corpus.py --out /tmp/ctrl.txt --categories 控制层,NOIP备考控制层,NOIP备考资料库,AI吞入包
# 自检（不写仓库）
python3 tools/export_ai_corpus.py --self-test
```

`_导出/` 已被 `.gitignore` 忽略：全文导出可以很大，但不进版本库，也不会污染 `01`/清单的哈希。

## 超大规模写入


导入规则、命名与「收件箱纪律」见 `../../备考资料库/README.md` 与 `../../仓库治理规范.md` §3。

## 边界（每次输出都要带上）

- 本包描述的是**仓库里写了什么**，不是「事实被证明了」。`[G]` / `ESTIMATE` / `CONFLICT` / `UNKNOWN` 不得升级为 `[OJ]`。
- `LOCAL-VERIFIED ≠ OJ AC`；`OJ AC ≠ 数学证明`；`Replay 保存 ≠ 提交`。
- 原始录屏、按键、剪贴板、完整聊天、账号页、OCR 原文与鉴权 URL **不在仓库中**，也不要向用户索取到公开仓库里。
- 结构自检：`python3 tools/verify_repo.py`；它不替代官方 OJ 回读、录像逐帧审阅或数学证明。
