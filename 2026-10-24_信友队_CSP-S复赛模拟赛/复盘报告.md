## 三、A 的成功模型

你明确先写 S=∏a_i，将条件转成 x|S 和 a_i|(S/a_i)×x。你把最大质因数贡献者称为“顶梁柱”，在样例 4,6,9 上先错算 16，再主动考虑某项被拿走后贡献不足，最终推到 9。

对质数 p：S_p=∑v_p(a_i)，M_p=max v_p(a_i)，e_p=v_p(x)；需且仅需 max(0,2M_p-S_p)≤e_p≤S_p。答案 ∏(S_p-max(0,2M_p-S_p)+1) mod 998244353。

本地 T1/main.cpp 以 mp[] 统计总指数、ma[] 统计最大指数，代码与数学对应；官方 20/20 AC。**这是真本领，不是碰巧猜公式。**

## 四、B 的主事故：正确 brute → 错误升级路线

### 数学内核：你已经做对
设某行原串 s_i，任意目标区间串 I（含空串），它需要的翻转列集合唯一为 x=s_i xor I；每行生成的 V_i 集合的交集是答案。你的投票记录 x 被多少去重后的行支持，筛选支持数==不同原串数，在数学上成立。重复行去重也合法。独立小范围穷举验证了这个对象。

### 丢失的关键结构：不需要高精度
第一行最多 B(B+1)/2+1 个区间结果，且 x 与第一行结果一一对应。因此答案不超过这个值；B≤2e6 时最大约 2×10^12，long long 足够。你在 15:46 起围绕 2^B/高精度想了较久，实际需计数的是首行的合法区间，而非全体 2^B 翻转集合。

### 根本复杂度
64 次以上 B main 保存记录显示：从 16:18 的字符串完整枚举到 16:45–17:15 的双哈希，再 17:17 回滚，17:22 后又优化字符串与恢复文件 IO，18:04 再交。
最终代码：
```cpp
for (auto y : s)
  for (int i=0; i<b; i++)
    for (int j=i; j<b; j++) {
      // flip candidate into temp
      vote[temp]++;
    }
```
候选数量最坏达 n'×B(B+1)/2，每个 std::map<string> key 又携带 O(B) 字符串复制、比较与存储，故不是你最初以为的“去重后 N 方”。即使 n' 小而 B 极大也会直接爆炸。OJ 在 11、13–20 MLE，与之吻合；通过点多是 small B，不构成 full 正确性保证。

### 双哈希并非“只是冲突”
源 WA.cpp 与 17:11 快照存在多处确定的实现错误：
- `add(left, y[i]-'0');` 返回值未赋回 `left`，左段哈希不变。
- `fac1/fac2` 只预计算到 `n+10`，却可能按 `b` 取下标；n 是去重行数，与列数 B 不等价。
- `pop(t,l)=t%fac[l-1]` 仅在**不发生模数回绕**的普通进制数字情况下才可直觉使用；已经 mod P 的 rolling hash 不允许这样任意弹头。
- P1、P2 都约 1e18，底数同为 2，并不提供可靠的独立双哈希；这是风险补充，不是本次零分的唯一证明。
- 更严重：即使修好了哈希，该路线仍然显式枚举 Θ(n'B²) 个候选，并没有把问题变成 O(nB) 或 O(nB+B²) 的端点判定。

这里是**替昂贵算法换昂贵表示**，而不是复杂度突破。此时不应继续局部 Debug，应回到“第一行方案 = 一个区间，只需两个端点”的对象。

### 真正通往正解的桥
固定首行零化：d_i=s_i xor s_1，选一个区间 I 使 d_i xor I 仍是一个区间。对各行做边界差分（两头加虚拟 0）；合法区间的差分恰好为 0 或 2 个 1，选区间相当于翻转两处差分位。若某行差分有≥6 个 1 无解；4 个 1 限制端点在有限候选；2 个 1 限制端点关系；0 个 1 没有限制。这就是官方题解压缩的原因。你不是错在“没想到 DP”，而是没有把从几百万个完整串的投票转换成**只有两个端点的约束交集**。

## 五、C 为什么可惜

录音在大约 B 研究中途有“瞄一眼第三题”的片段：注意到交换次数、理论上下界，并问某颜色只有一张的情况。对单个蓝卡，最终可以将它停在环上任何座位，最优取最大 w；单个白卡，最终也可停在任意位置，最优是全部 w 之和减去最小 w。相同分值时按照最终 01 串字典序选位置。

本题 1–4 点 n≤8（20 分），可用枚举 n! 种边检查顺序的独立暴力；11–14 点“一种颜色恰一张”（20 分），上述 O(n) 特判可完整解决性质。**合计覆盖 40 分的明确路线**，其中与 1 号点有交叠，不可重复累计，按测试点并集为 1–4 与 11–14 共 8 点，即40分。录音里确实讨论性质 A，但没有在赛中编码、验证和冻结，40 是赛后已验证可行路线，并非赛时“稳到手”。

C 真实提交 Dangerous Syscall 20/20，大小 1046 字节，与 B 最后源文件 1046 字节**完全相同**。结合时间相差仅 23 秒、当时 B 代码开着 lamps.in/out，以及平台 C 源码隐藏，最佳表述是“高度疑似贴错题源码或误用 I/O”，不能当作直接获得 406892 的源码。无论哪种，提交层有严重事故，应设置代码题名/文件名/本地编译检查点。

本题正解入口：令 t_i=检查第 i 条边时是否交换，最终 b_i=s_i+t_{i-1}-t_i，环上 t_0=t_n；在 s_i=1、s_(i+1)=0 时还强制 t_i=1；枚举环边界 t_0∈{0,1}，做二状态后缀 DP 并字典序重建，O(n)。

## 六、D 为什么可惜

本地 T4/main.cpp 截止 Replay 停止仍是空模板；屏幕晚期关键帧也显示 T4 空工程；OJ 406904 是 274 字节 WA 全点、源码隐藏，故不能宣称“已写过正确 D 算法”。

其小规模分原本有清晰路线：对 n≤18，用集合 DP，dp[mask] 表示已放在前面的卡组成 mask 时最小分界费用，新增本步费用（非完整集合时）为 max_{i∈mask}a_i + max_{i∉mask}b_i。可预计算每个子集 max，时间 O(n2^n)，内存 O(2^n)，覆盖测试点 1–4 的 20 分。性质 A（所有 a 严格递增且 b 严格递减）可按 a 递增排序，覆盖测试点 13–14 的 10 分，合计 30 的候选路线。上述都已做小 n 独立枚举检验，但不是赛时曾写出。
满分原理：删除受支配卡，关键卡构成 a 增、b 减链；其余卡分别选择插入间隙，付出 max(a,α_j)+max(b,β_j) 的最小增量；二分边界并以 RMQ 求中间区间最小值，总体 O(n log n)。本场最后没有时间做这个转换，D 更应抢先完成可验证 partial。
